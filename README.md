# Мои заметки :)

Приложение для заметок на **Nuxt 4**, **Pinia** и **SCSS**.
Заметки оформлены как стикеры Post-it на пробковой доске.

## Запуск

```bash
cd docker
docker-compose up --build
```

или из корня репозитория:

```bash
docker-compose -f docker/docker-compose.yaml up --build
```

Приложение откроется на <http://localhost:8080>.

Локально (Node ≥ 20.19):

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # Vitest
npm run typecheck  # vue-tsc
npm run lint       # ESLint (@nuxt/eslint, flat config); lint:fix — с автоисправлением
npm run format     # Prettier; format:check — только проверка
npm run generate   # статическая сборка в .output/public
```

## Возможности

**Главная (`/`)** — доска со стикерами: заголовок, прогресс, первые 4 пункта и «и ещё N пунктов». Можно создать заметку, перейти к изменению и удалить
её.

**Редактор (`/notes/:id`, новая заметка — `/notes/new`)**:

- сохранить (`Ctrl+S`), отменить редактирование, удалить;
- undo / redo (`Ctrl+Z` / `Shift+Ctrl+Z`, а также `Ctrl+Y` и `⌘` на macOS; работает и в русской раскладке);
- пункты Todo: добавить, удалить, изменить текст, отметить выполненным;
- цвет стикера;
- клавиатура: `Enter` в пункте создаёт следующий, `Backspace` в пустом пункте удаляет его, `↑/↓` переходят между полями;
- уход со страницы с несохранёнными изменениями требует подтверждения.

### История изменений

- Хранятся **операции (дельты)**, а не снимки: `setTitle {from,to}`, `setTodoDone`, `addTodo {index, todo}`,
  `removeTodo`, `setColor`… Каждая операция знает, как себя обратить. 50 шагов — это 50 маленьких объектов,
  а не 50 копий заметки.
- Непрерывный ввод в одно поле — **одна** запись: фиксация по `blur`, паузе ввода 700 мс, переходу в другое поле
  или по любому атомарному действию.
- Чекбокс, добавление и удаление пункта, смена цвета — отдельные атомарные записи.
- Новое изменение после undo очищает redo-ветку. Лимит — 50 шагов (старые отбрасываются).
- «Сохранить» и «Отменить редактирование» сбрасывают историю.
- **Конфликт с нативным undo**: пока в текстовом поле идёт незафиксированный ввод, `Ctrl+Z` отдаётся
  браузеру (нативная отмена набранного). Как только ввод зафиксирован, `Ctrl+Z` откатывает историю заметки —
  с любого места страницы. Когда открыта модалка, хоткеи не срабатывают.

### Хранилище

- `localStorage`, ключ `mkb-notes:data`, формат `{ version: 1, notes: [...] }`.
- Запись не на каждое изменение: изменения копятся и пишутся с задержкой 300 мс (debounce),
  принудительно — при `pagehide` / скрытии вкладки.
- При загрузке данные валидируются и мигрируют (пример: версия 0 — массив без обёртки). Повреждённые
  данные не роняют приложение и сохраняются в резервный ключ. Ошибка записи (переполнение) показывается баннером.
- **Черновик**: несохранённое редактирование пишется в `mkb-notes:draft:<id|new>`. После перезагрузки
  предлагается восстановить его (с предупреждением, если заметка с тех пор менялась в другом месте).

### Edge-cases

- **Несуществующая заметка по URL** — экран «Заметка не найдена» с переходом на доску или к созданию; неизвестные
  маршруты — страница 404.
- **Пустое название** сохраняется как «Без названия»; **пустые пункты** выбрасываются при сохранении; полностью
  пустую заметку сохранить нельзя.
- **Удаление во второй вкладке**: вкладки синхронизируются через событие `storage`. Если открытую на
  редактирование заметку удалили в другой вкладке, правки не теряются — появляется модалка
  «Сохранить как новую / Продолжить редактирование».
- При одновременном редактировании одной заметки в двух вкладках действует правило «последнее сохранение побеждает».

### Доступность

Собственные модальные окна (`BaseModal`): `role="dialog"`/`alertdialog`, `aria-modal`, focus-trap, закрытие по
`Escape`, возврат фокуса, блокировка прокрутки. Фокус по умолчанию — на безопасной кнопке. Все действия доступны
с клавиатуры, видимый `:focus-visible`, чекбоксы — нативные `input`, учитывается `prefers-reduced-motion`
и тёмная тема (`prefers-color-scheme`).
